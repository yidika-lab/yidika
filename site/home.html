Write it once. Run it now, or ship it native.

Yidika is a typed language with one tool, yidi. Start a program at once in the interpreter, or compile it through LLVM into a native binary as fast as Rust. Both engines print the same output, and the test suite checks that they do.

Speed

Native speed, measured

yidi run compiles the program through LLVM, caches the binary and runs it. The same function built with rustc -O takes the same time.

Best of three runs on an AMD Ryzen 5 4500U, Linux. Run the benchmark yourself.

yidi, native
0.034 s
Rust, rustc -O
0.036 s
yidi, interpreter
11.3 s

Bars to scale: the native run is 330 times shorter than the interpreter run.

One tool

Everything goes through yidi

Running, compiling, watching, projects, packages and upgrades are one command. No build file to write, and a built program needs no runtime installed next to it.

Every command{{icon:arrow-right:14}}
yidi app.yk
Type-check, compile to native code, cache and run.
yidi app.yk --watch
Run again each time a file of the program is saved.
yidi build app.yk
Write a standalone executable next to the source.
yidi run app.yk --interp
Start at once in the interpreter, no compiler needed.
yidi init, yidi add
Create a project and add packages, pinned in yidi.lock.
yidi upgrade
Install the latest release after checking its SHA-256.

Two engines

One program, two ways to run it

  1. Checked first. yidi parses and type-checks the whole program. An error stops here, with the file, line and column.
  2. Native when it can. The program is compiled to LLVM IR, linked and cached; the next run starts the cached binary.
  3. Interpreter otherwise. If the native backend does not support something yet, yidi run says so and runs the interpreter instead of a wrong binary.

Packages

Packages from git, checked by hash

A package is a git repository with a tag. The registry records which commit is which version and the SHA-256 to expect; yidi.lock pins both. One cache serves every project, so a second install needs no network.
