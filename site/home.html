Yidika

yidika, Kikongo: to design, to arrange, to put back in order.

A statically typed language. Run a program straight away in the interpreter, or let yidi arrange it into native code through LLVM. Both engines print the same output, and the test suite checks that they do.

curl -fsSL https://raw.githubusercontent.com/yidika-lab/yidika/main/install.sh | sh
irm https://raw.githubusercontent.com/yidika-lab/yidika/main/install.ps1 | iex
cargo install --git https://github.com/yidika-lab/yidika yidi

Speed

Native speed, measured

yidi run compiles the program above through LLVM, caches the binary and runs it. The same function built with rustc -O takes the same time.

Best of three runs on an AMD Ryzen 5 4500U, Linux. Run the benchmark yourself.

yidi, native
0.034 s
Rust, rustc -O
0.036 s
yidi, interpreter
11.3 s

Bars to scale: the native run is 330 times shorter than the interpreter run.

Two engines

One program, two ways to run it, the same output

  1. Checked first. yidi parses and type-checks the whole program. An error stops here, with the file, line and column.
  2. Native when it can. The program is compiled to LLVM IR, linked and cached; the next run starts the cached binary.
  3. Interpreter otherwise. If the native backend does not support something yet, yidi run says so and runs the interpreter instead of a wrong binary.

Packages

Packages from git, checked by hash

A package is a git repository with a tag. The registry records which commit is which version and the SHA-256 to expect; yidi.lock pins both. One cache serves every project, so a second install needs no network.
